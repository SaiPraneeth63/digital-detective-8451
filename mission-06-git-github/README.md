## 3. Commands / tools used
- `git status`: Inspects the current state of the working directory and staging area.
- `git checkout -b <branch>`: Creates and switches to a new branch.
- `git add`: Stages specified file changes.
- `git commit`: Records staged changes permanently to the local repository history.
- `git push`: Uploads local branch commits to the remote GitHub repository.
- `git pull`: Fetches and integrates remote changes into the local working environment.

## 4. My understanding
Git provides reliable version control by tracking incremental changes locally, while GitHub enables collaborative remote hosting. Branches allow developers to work on new features or updates safely without disrupting the main production code. Pull Requests provide a structured mechanism for reviewing, discussing, and merging code changes.

### Task 6.4: Git Command Glossary
| Git Operation | Explanation in Your Own Words |
| :--- | :--- |
| Initialise a repository (`git init`) | Creates a new local Git repository in a project folder. |
| Check status (`git status`) | Displays modified, staged, or untracked files in the workspace. |
| Stage changes (`git add`) | Marks specific file changes to be included in the next commit. |
| Commit changes (`git commit`) | Saves staged changes with a descriptive message to the local history. |
| View history (`git log`) | Displays the chronological list of past commits and their metadata. |
| Create/list branches (`git branch`) | Lists existing local branches or creates a new one. |
| Switch branches (`git checkout`) | Moves working context between different branches. |
| Publish changes (`git push`) | Uploads local commits to the remote GitHub server. |
| Retrieve remote changes (`git pull`) | Fetches and merges updates from the remote repository to the local machine. |
